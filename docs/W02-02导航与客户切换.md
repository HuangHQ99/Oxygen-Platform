# W02-02 桌面与手机导航及客户切换

**状态：待验收。** 本卡提供可运行的响应式工作区外壳，用合成身份和授权数据验证 W01-03 的多客户、多数据中心及按客户独立角色。真实登录、服务端授权、数据库租户隔离和撤权即时生效由 W02-03 继续实现。

## 本卡结果

- 电脑 Web 使用固定侧边导航，手机 Web 使用底部主要导航；两端共用 Vue 3 代码、路由和状态模型。
- 页面持续显示当前客户和当前数据中心。选择会话内保存，刷新页面仍保留；无效或不属于当前客户的数据中心不会被接受。
- 切换客户会重置数据中心为“全部已授权数据中心”、递增页面上下文版本、重建业务页面，并提示上一客户的页面条件与临时上下文已清除。
- 导航按当前客户下的角色重新计算。若当前页面在新客户中不可访问，路由自动返回工作台。
- 后端提供明确标记 `demoMode: true` 的合成工作区接口，供全栈演示和回归测试使用。它不是授权判断，不返回真实客户业务数据。

## 合成验收身份

登录展示身份为 `Aiman Rahman`，职位快照为 `Maintenance Lead / Field Engineer`。身份在不同客户下具有独立授权：

| 当前客户 | 数据中心范围 | 当前客户角色 | 应显示的主要模块 |
|---|---|---|---|
| 客户 A（合成） | A1、A2 | 服务商维保负责人、服务商现场工程师 | 工作台、设备资产、维保计划、维保工单、维保报告 |
| 客户 B（合成） | B1 | 服务商现场工程师 | 工作台、维保工单、维保报告 |

设备资产入口对服务商管理员或维保负责人显示。现场工程师完成指派任务所需的设备资料后续从工单上下文进入，不因此获得资产主数据模块。报告入口可供现场工程师查看包含本人执行记录的报告；签发动作仍只允许维保负责人，须由后端逐动作判权。

## 导航与上下文生命周期

1. Web 启动时调用 `GET /api/v1/navigation/bootstrap`，取得展示身份、默认客户以及每个客户各自的角色和数据中心范围。
2. 浏览器只在 `sessionStorage` 的 `oxygen.workspace.v1` 中保存当前客户 ID 和数据中心 ID；关闭会话后不承诺保留。页面不缓存授权为可信安全凭据。
3. 恢复会话时，前端用最新 bootstrap 响应重新校验已保存选择；客户或数据中心不再存在时，回退到服务端默认客户和“全部已授权数据中心”。
4. 切换数据中心只允许当前客户授权集合中的 ID。数据中心改变后重建业务页面上下文；切换客户时不沿用原数据中心，即使代码或名称相同。
5. 业务页面挂在范围上下文版本上。客户或数据中心改变后 Vue 重新创建页面组件，避免旧范围的筛选条件和临时页面状态继续显示。
6. 启动、刷新、切换客户或直接输入地址时均重新核对当前角色导航。目标模块在当前客户不可用时自动返回工作台；这只是界面收敛，后端仍须独立拒绝未授权请求。
7. W02-03 接入真实身份后，每个业务 API 仍必须依据服务端当前授权判权；前端隐藏菜单只改善体验，不能代替安全控制。

## 正常与拒绝验收例

1. 在电脑宽度打开工作台，客户 A 显示左侧五个主要模块、A1/A2 两个数据中心以及两个当前角色。
2. 在手机宽度打开同一地址，显示同一客户选择器和底部五项导航，页面无横向溢出。
3. 在客户 A 选择 A2，刷新页面仍显示 A2；切到客户 B 后数据中心重置为全部范围，列表只含 B1。
4. 从客户 A 的维保计划页切到客户 B，系统自动返回工作台，设备资产和维保计划入口消失，并显示清理提示。
5. 客户 B 会话直接打开或刷新 `/plans` 时仍自动返回工作台，不能仅靠隐藏菜单绕过页面收敛。
6. 代码尝试在客户 B 上选择 A1 时，状态层拒绝请求并保持当前数据中心不变。
7. bootstrap 接口不可用时，页面显示 API 未启动提示，不使用陈旧授权继续构造业务入口。

## 验收演示

1. 启动 PostgreSQL、Spring Boot 和 Web 开发服务器，打开 `http://localhost:5173/`。
2. 确认页首为“客户 A（合成）”，侧边栏或手机底栏包含设备、计划、工单和报告。
3. 打开“维保计划”，把当前客户切换为“客户 B（合成）”。
4. 确认地址回到工作台，出现“上一客户的页面条件与临时上下文已清除”，且设备资产和维保计划入口不再出现。
5. 切回客户 A，选择 A2 数据中心并刷新，确认当前客户及数据中心选择仍正确。
