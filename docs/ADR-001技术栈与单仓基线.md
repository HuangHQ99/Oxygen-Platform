# ADR-001：技术栈与单仓基线

- 状态：已采纳
- 日期：2026-11-23
- 决策人：项目负责人
- 适用范围：Oxygen V1

## 背景

Oxygen 由一名负责人配合 AI 开发，需要同时支持电脑浏览器和现场工程师手机浏览器，并以较低的早期云成本运行。V1 的重点是资产录入、维保计划和分发、现场执行及正式报告，不需要原生 App 独有能力。后续业务包含多客户隔离、状态流转、排程、审计和 PDF 生成，后端需要明确事务边界。

## 决策

- 后端采用 Java 21、Spring Boot 和 Maven 多模块模块化单体。
- 前端采用 Vue 3、TypeScript 和 Vite，以一套响应式 Web 应用适配电脑和手机。
- V1 不创建 UniApp 或独立原生 App；短时断网草稿在 Web/PWA 能力内实现，正式提交必须联网。
- 数据库采用 PostgreSQL，结构迁移采用 Flyway。
- 仓库采用 pnpm workspace + Maven Wrapper 的单仓结构，前后端共享版本、CI 和交付记录。
- 初始模块边界为 domain、application、infrastructure、worker 和 boot；在有测量证据前不拆微服务。
- API 以 `/api/v1` 版本化，OpenAPI 契约和生成的 TypeScript 客户端放在 `contracts/openapi` 边界。

## 原因与影响

Spring Boot 适合承载事务、调度、权限和报告后台任务；Vue 让同一小团队维护一套桌面／手机界面；模块化单体比微服务减少部署、观测和数据一致性成本。取消第二套 UniApp 代码可以避免页面、校验和权限逻辑重复。

代价是首版后端的内存占用高于极简运行时，原生扫码／RFID 能力受浏览器及硬件支持约束。RFID 读写器接入需在硬件选型时验证；如必须使用原生能力，应另写 ADR，说明业务证据、维护成本和迁移边界。

## AI 变更约束

AI 可以在上述框架内新增模块、依赖和工具，但必须说明直接依赖解决的问题，并保持锁文件与测试入口同步。替换 Spring Boot、Vue、PostgreSQL、Maven 或 pnpm，拆分微服务，或新增 UniApp／原生移动端，均须先提交 ADR 并由项目负责人确认，不能在普通功能卡中顺带完成。
