**状态：待验收。** 本卡已完成本地身份与客户隔离链路、ARM64 应用镜像、AWS 云资源、运行编排、

本机 `oxygen-preprod` profile 使用 IAM Identity Center 临时会话，业务资源位于马来西亚
`ap-southeast-5`。预发布入口为 <https://di33rkoicdx1o.cloudfront.net>。

## 本卡结果

- 浏览器未登录访问业务 API 返回 401，页面提供登录入口。本地演示账号仅用于开发；预发布使用
  Cognito OIDC 配置。
- 身份、服务商人员、客户授权、授权角色、授权数据中心、设备均已进入 PostgreSQL；导航内容不再由
  后端硬编码。
- 一个请求携带一个客户 ID，但服务端用已验证身份、授权状态、有效期和数据中心范围再次判权。客户
  ID 与设备归属不一致统一返回 404，避免枚举其他客户资产。
- Aiman 具备客户 A/B 授权；Lina 只有客户 A。集成测试证明 Lina 能读取客户 A 的
  `FM200-001`，探测客户 B 设备返回 404。
- Flyway V2 使用完全合成的数据建立 A/B 客户、A1/A2/B1 数据中心及同业务编码设备；不包含客户
  真实资料。
- AWS CDK 已在马来西亚 `ap-southeast-5` 建立 Cognito 托管登录域、CloudFront HTTPS
  入口、ECR、单台 `t4g.micro`（2 GiB swap）、20 GiB 加密 EBS、Secrets Manager、加密版本化
  S3 备份、SSM 与每月 20 USD 的 80% 预测／100% 实际费用邮件告警。无 NAT Gateway、负载均衡器
  和 SSH 入站。
- API 与 Web 镜像均已按 `linux/arm64` 构建并推送 ECR。EC2 当前运行 `stable` 标签，readiness 失败
  自动恢复上一组应用镜像；PostgreSQL 每日备份入口和需要人工输入 `RESTORE` 的恢复入口已建立。

## 本地演示

1. 启动 PostgreSQL：`docker compose up -d postgres`。
2. 启动 API：`./mvnw -pl backend/oxygen-boot -am spring-boot:run`。
3. 启动 Web：`pnpm dev`，打开 `http://localhost:5173/plans`。
4. 点击“登录”，输入 `aiman / local-only-change-me`。登录后打开“维保计划”，客户 A 可见
   A1/A2，客户 B 仅可见 B1。
5. 设备证明接口：
   `GET /api/v1/clients/20000000-0000-0000-0000-00000000000a/assets/60000000-0000-0000-0000-00000000000a`
   返回 `FM200-001`。将客户改为 B 而保留资产 A 时返回 404。

开发密码可通过 `OXYGEN_DEMO_PASSWORD` 覆盖，禁止用于预发布或生产。云环境启用
`SPRING_PROFILES_ACTIVE=oidc` 与 `OXYGEN_AUTH_MODE=oidc`，并从秘密配置注入 Cognito issuer、
client ID 和 client secret。Cognito 用户建立后必须以不可变 OIDC subject 关联 Oxygen 人员记录；
示例映射只用于本地演示。

## 云部署边界与成本

当前 CDK 是低成本预发布方案：Web、API、PostgreSQL 同机，节点故障会整体不可用，不满足生产高
可用或灾备要求。正式生产前至少需要完成自动快照与恢复演练、数据库迁移到受管 RDS、跨可用区、
监控告警、镜像发布／回滚和数据库业务角色/RLS。

预计新增收费项是 EC2、20 GiB EBS、公网 IPv4、CloudFront 流量、ECR 存储、Secrets Manager 与
备份；Cognito 按实际活跃用户计费。2026-11-24 通过 AWS Pricing API 实查 `t4g.micro` 为
`0.0095 USD/小时`，计算部分约 `6.94 USD/月`，当前低流量总估算约 `13–15 USD/月`。模板中的
20 USD 是告警阈值而非强制停机上限。详见[部署与恢复手册](W02-03预发布部署与恢复.md)。

## 实际验证证据

- `./mvnw --batch-mode --no-transfer-progress verify`：通过；Java 21、真实 PostgreSQL 17.7、Flyway
  V1/V2、登录会话、A/B 隔离与 Checkstyle 均通过。
- `pnpm check`：通过；格式、ESLint、类型、5 个 Web 单测、1 个 CDK 断言测试及生产构建通过。
- `OXYGEN_E2E_REAL_API=true pnpm --filter @oxygen/web test:e2e`：桌面 Chromium 与 Pixel 7 两项
  通过；走真实表单登录、API、PostgreSQL、设备读取、客户切换及 readiness。
- `pnpm --filter @oxygen/infra synth`：通过；仅生成 CloudFormation，没有连接或修改 AWS。
- `docker build --platform linux/arm64`：API 与 Web 均通过并确认镜像架构为 arm64。隔离启动
  PostgreSQL 17.7、API、Web 后，API readiness 和经 Web 代理的 readiness 均返回 `UP`，首页标题
  为 Oxygen；临时容器与网络已清理。
- CloudFormation：`OxygenBudget` 在 `us-east-1` 创建全局账单告警，`OxygenPreprod` 在
  `ap-southeast-5` 创建业务资源。预算实查为 20 USD/月、80% 预测和 100% 实际告警。
- 公网验收：首页标题为 Oxygen，readiness 返回 HTTP 200／`UP`，未登录 bootstrap 返回 401，登录
  入口返回 303 到 Cognito；绕过 CloudFront 直接访问源站返回 403。
- 运行验收：首次启动暴露 Docker 网络缺少 `postgres`／`api` 别名，提交 `ce1644e` 增加别名和回归
  测试；修复后 PostgreSQL、API、Web 均保持运行，服务发布标记为 `stable`。
- 备份验收：2026-11-25 手工触发备份成功，S3 对象为 PostgreSQL custom-format；
  `pg_restore --list` 读取成功，共 56 个目录项。未覆盖运行数据库。
- 云端基线 CI：[GitHub Actions #15](https://github.com/HuangHQ99/Oxygen-Platform/actions/runs/45422533921)
  的后端、前端和全栈浏览器作业全部通过。DNS 修复提交后，使用仓库固定 Node 运行 `pnpm check`，
  5 个 Web 测试、4 个基础设施测试、类型检查、Lint 和生产构建均通过；对应推送 CI 另见提交检查。
